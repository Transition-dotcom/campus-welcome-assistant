# 部署说明

> 项目：大学萌新领航站（东北大学软件学院 · 校园新生服务平台）
> 架构：FastAPI 后端（8080）+ Vue 3 前端（5173）+ MySQL 8
> 本说明覆盖本地开发启动与生产部署建议，所有命令以项目根目录 `campus-nav/` 为基准。

---

## 1. 环境要求

| 依赖 | 版本要求 | 说明 |
|------|---------|------|
| Python | 3.9+ | 建议使用 venv 虚拟环境（项目自带 `backend/venv/` 可直接复用） |
| Node.js | 18+ | 前端构建与开发服务器（Vite 5） |

## 2. 数据库初始化

默认连接配置（`backend/app/config.py`）：`localhost:3306`，用户 `root`，密码 `root`，库名 `campus_nav`。

```bash
mysql -u root -proot --default-character-set=utf8mb4 < backend/init.sql
```

**注意事项**：

1. **必须加 `--default-character-set=utf8mb4`**：种子数据含大量中文，缺少该参数会报编码错误（`Incorrect string value`）；
2. 脚本幂等：开头 `CREATE DATABASE IF NOT EXISTS campus_nav`（utf8mb4 / utf8mb4_unicode_ci），全部 `CREATE TABLE IF NOT EXISTS`；
3. 种子数据规模：25 门课程、15 个社团、19 条社团活动、14 个地标、8 条路径、5 篇攻略、12 项新生任务、5 条安全提示、10 条课程评价、1 个管理员账号；
4. `club_event.event_time` 使用 `DATE_ADD(NOW(), INTERVAL n DAY)` 相对时间写入，**任何时候初始化，招新日历都不会因过期而显示为空**；
5. 完成后脚本会输出 `东北大学软件学院版数据库初始化完成！`；
6. 若密码不是 root：用 `-p` 交互输入，或先改 `backend/.env` 中的 `DB_PASSWORD` 再启动后端；
7. 应用启动时还会执行 `Base.metadata.create_all()` 兜底补建缺失的表（不覆盖已有表）。

## 3. 后端启动（端口 8080）

### 3.1 创建虚拟环境并安装依赖

```bash
cd backend
python3 -m venv venv            # 本项目已自带 venv/，可直接跳到激活
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 3.2 启动服务

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8080 --reload
```

- 健康检查：<http://localhost:8080/>（返回 `{"message": "大学萌新领航站 API 运行中", ...}`）
- 详细健康检查：<http://localhost:8080/health>（含数据库连通性）
- Swagger 文档：<http://localhost:8080/docs>

### 3.3 配置项（`backend/app/config.py`）

所有配置通过环境变量或 `backend/.env` 文件覆盖（`pydantic-settings`，环境变量名与字段名对应，大小写不敏感）：

| 配置项 | 环境变量 | 默认值 | 说明 |
|--------|---------|--------|------|
| db_host | DB_HOST | localhost | MySQL 主机 |
| db_port | DB_PORT | 3306 | MySQL 端口 |
| db_user | DB_USER | root | MySQL 用户名 |
| db_password | DB_PASSWORD | root | MySQL 密码 |
| db_name | DB_NAME | campus_nav | 数据库名 |
| jwt_secret | JWT_SECRET | （空） | JWT 签名密钥，生产环境必须显式设置 |
| jwt_algorithm | JWT_ALGORITHM | HS256 | JWT 签名算法 |
| access_token_expire_minutes | ACCESS_TOKEN_EXPIRE_MINUTES | 120 | access_token 有效期（2 小时） |
| refresh_token_expire_days | REFRESH_TOKEN_EXPIRE_DAYS | 7 | refresh_token 有效期（7 天） |
| cors_origins | CORS_ORIGINS | http://localhost:5173,http://127.0.0.1:5173 | 允许跨域来源（逗号分隔） |

`.env` 示例：

```bash
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=你的密码
DB_NAME=campus_nav
JWT_SECRET=请生成一个足够长的随机字符串
CORS_ORIGINS=http://localhost:5173
```

**JWT_SECRET 自动生成机制**（`backend/app/main.py`）：

- 未设置 JWT_SECRET 时，启动会自动生成随机密钥并**写入 `backend/.env`**（追加 `JWT_SECRET=...`），下次启动复用同一密钥，**重启后 token 不失效**；
- 若写入 `.env` 失败（如只读文件系统），会使用临时密钥并告警，此时重启后所有 token 失效；
- 生产环境务必通过环境变量显式设置固定强随机密钥（多 worker/多实例必须一致，见 §5.2）。

### 3.4 连接池

`backend/app/database.py`：`pool_size=10`、`max_overflow=20`、`pool_pre_ping=True`（连接前探活），SQL 日志默认关闭。

## 5. 生产部署建议

### 5.1 前端：Nginx 托管 dist + 反代 /api

前端使用 Vue Router 的 `createWebHistory()`（history 模式），**Nginx 必须配置 SPA fallback**，否则刷新 `/courses` 等深层路由会 404：

```nginx
server {
    listen 80;
    server_name your.domain.com;

    # 前端静态资源（npm run build 的产物）
    root /var/www/campus-nav/dist;
    index index.html;

    # SPA fallback：history 路由刷新回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理到后端
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

### 5.2 后端：多 worker 运行

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8080 --workers 4
```

- 多 worker 时**必须显式配置 `JWT_SECRET`**：密钥不一致会导致不同 worker 签发的 token 互相验证失败（401）；也不要依赖「自动写入 .env」机制在生产环境兜底；
- 生产建议使用 systemd / supervisor 守护进程；`--reload` 仅用于开发。

### 5.3 限流在反向代理后的说明（提示性）

登录/注册接口的限流（10 次/分钟/IP，见 `backend/app/middleware/rate_limit.py`）基于 `request.client.host`，即**直连对端 IP**。部署在 Nginx 之后时，后端看到的 IP 全部是 Nginx 地址，限流会退化为全局共享配额。如需按真实用户 IP 限流，需要引入代理协议（如 `uvicorn --proxy-headers` + 中间件读取 `X-Forwarded-For`）或改用网关层限流。限流器为内存实现，仅适用于单机部署；多实例部署时各实例独立计数。

## 7. 常见问题排查

| 现象 | 原因与处理 |
|------|-----------|
| 端口被占用 `address already in use` | `lsof -i :8080`（后端）/ `lsof -i :5173`（前端）/ `lsof -i :3306`（MySQL）找到占用进程后 `kill` 或换端口 |
| 导入 init.sql 报 `Incorrect string value` | 未加 `--default-character-set=utf8mb4`；重新按 §2 命令导入 |
| 页面中文乱码 | 数据库/表/连接字符集不一致；确认 init.sql 用 utf8mb4 导入，后端连接串已带 `?charset=utf8mb4`（config.py 自动拼接） |
| MySQL 认证失败 `caching_sha2_password` | MySQL 8 默认认证插件；新版 PyMySQL（1.1.1）已支持，若仍失败可将用户改为 `mysql_native_password`：`ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'root';` |
| 所有请求突然 401 | 多半是 `JWT_SECRET` 变化导致旧 token 全部失效（例如删除 `backend/.env` 后重启生成了新密钥）；重新登录即可，或固定 JWT_SECRET |
| 登录/注册返回 429 | 触发了限流（10 次/分钟/IP），等待 1 分钟后重试；正常使用不会触发 |
| 前端请求跨域报错 | 检查后端 `CORS_ORIGINS` 是否包含前端地址（默认只放行 localhost:5173）；修改后需重启后端 |
| 后端启动时数据库连接报错 | 确认 MySQL 已启动、账号密码正确、`campus_nav` 已初始化；可用 `GET /health` 确认连通性 |
| 前端 404（直接访问深层路由） | 生产环境 Nginx 未配 `try_files` fallback，见 §5.1；开发环境 Vite 自带处理 |
| 数据库操作报 400「数据冲突或重复」 | 唯一键冲突（如重复昵称/学号/重复点赞），为全局异常处理器的友好提示 |
